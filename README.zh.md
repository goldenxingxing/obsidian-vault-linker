# Vault Linker Auto

[English](README.md) · 中文

**让 Obsidian 笔记自动互相连起来——链接是普通 Markdown，你写的内容一个字都不改。**

Vault Linker 在笔记之上维护一层「链接」：给 vault 的每个领域生成一个索引页，在每篇笔记末尾列出几篇
「相关文档」，按两篇笔记共享的主题排序。vault 有变化时它会自动更新；它写的所有内容都放在带标记的区块里，
随时可以重写或删除。

## 亮点

- **不改你写的内容。**只在自己的区块里写。每次写完都逐字节核对：去掉区块后的笔记必须和原来一模一样，
  否则立即还原。
- **链接就是普通 Markdown。**链接写在文件里，不存在插件的数据库里，grep、git、脚本、AI agent 和别的
  应用都能看到。卸载插件，链接还在。
- **零配置就能用。**顶层目录自动成为领域；笔记标题、别名和标签就是用来判断相关性的主题。`README`、
  `index`、日期这类说明不了笔记讲什么的名字会被自动忽略。
- **从你的笔记里挖出你的术语。**「从笔记里找」不需要词典，中英文都能从 vault 里挖出候选术语，由你勾选。
- **不漏掉 Obsidian 之外的改动。**脚本、同步工具、AI agent 写的文件未必触发 Obsidian 的文件事件，
  所以另有轮询兜底。
- **快，而且不打扰。**800 篇约 1 秒、3000 篇约 6 秒，分段计算，Obsidian 不会卡住。结果确定：
  连跑两次第二次零改动；只有日期变了不重写索引页，git 历史保持干净。
- **对你的 vault 很小心。**装好后默认什么都不做；不覆盖不是它生成的文件；跳过模板、Excalidraw 画板、
  Kanban 看板和你正在编辑的笔记；保留 Windows 换行。
- **不联网、可移植。**不联网、无遥测、零运行时依赖，手机上也能用。界面跟随 Obsidian 的语言（中文或英文）。

## 写进笔记的样子

笔记末尾：

```markdown
---
<!-- AUTO-LINKS:START -->
## 相关笔记

- 导航：[[_moc/项目]]
- [[项目/缓存改造|缓存改造]]
- [[调研/淘汰策略对比|淘汰策略对比]]
<!-- AUTO-LINKS:END -->
```

`_moc/` 下每个顶层文件夹一个索引页，子文件夹各成一节，另有一个 `主页`；vault 根目录下的笔记列在 `其他笔记` 里：

```markdown
# 项目

> 本页由 Vault Linker 自动生成，请勿手工编辑。

- [[项目/路线图|路线图]] — 今年计划做的事…

## 搜索

- [[项目/搜索/二期|搜索二期]] — 搜索第二版的目标…
```

文件夹改名或删掉后，下一次运行会把它的旧索引页移到回收站。只会删插件自己生成的页面。

## 和常见自动链接插件的区别

| | 常见自动链接插件 | Vault Linker |
|---|---|---|
| 怎样算相关 | 一篇提到了另一篇的标题 | 两篇共享的主题，越少见的主题权重越高 |
| 链接写在哪 | 改写正文，插入行内链接 | 文末的受管区块，正文不动 |
| 排序 | 无 | 共享主题越少见得分越高，同领域加分，取前 N 篇 |
| 索引页 | 一个目录一个（如果有） | 一个领域一个，多个目录可合成一个领域，每篇附一行摘要 |
| 连跑两次 | 多为「跳过已有链接」 | 严格幂等：区块整体重建，第二次零改动 |
| Obsidian 之外改的文件 | 没有文件事件就漏掉 | 轮询兜底 |

## 安装

插件还没有上架社区插件库。

**从 Release 安装**

1. 在 [最新 Release](https://github.com/goldenxingxing/obsidian-vault-linker/releases/latest)
   下载 `main.js`、`manifest.json` 和 `styles.css`。
2. 放进 `<你的 vault>/.obsidian/plugins/vault-linker-auto/`（`.obsidian` 是隐藏目录；macOS 访达里按
   `⌘ ⇧ .` 显示）。
3. 在 Obsidian 里：**设置 → 第三方插件 → 已安装插件 → 启用 Vault Linker Auto**。

**用 BRAT 安装**（自动更新）：装好 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 插件，
选「Add beta plugin」，填 `goldenxingxing/obsidian-vault-linker`。

**从源码构建**：`npm install && npm run build`，再像上面一样拷贝 `main.js`、`manifest.json` 和 `styles.css`。

## 上手

启用后插件**不会自动改动任何文件**。

1. 打开 **设置 → Vault Linker Auto**。
2. 点 **预览**，看它会改什么，这一步不写盘。
3. 满意后点 **更新链接**。
4. 想让它随你写作自动更新，打开 **自动更新**，再选停下来多久后更新（30 秒到 1 小时）。

要配置的就这些。设置页一共七项：立即运行、自动更新、停下来多久后更新、每篇笔记的相关链接数、索引页、跳过的文件夹、可选的主题词。
每个顶层文件夹自动有自己的索引页，之后新建的文件夹也一样。更细的参数（打分、生成的文字、时机）
都有合适的默认值，放在设置 JSON 里：**导出**、修改、再 **导入**。

每次运行后的报告会列出改了什么、跳过了什么、为什么跳过；每次运行也会追加到
`.obsidian/plugins/vault-linker-auto/vault-linker.log`。

## 安全机制

每次写入都经过这些检查：

- **先预览。**不点「更新链接」、不开「自动更新」，就什么都不写。
- **变了就跳过。**预览之后被改过的笔记，这次不动。
- **写后核对，出错还原。**写完后，去掉区块的笔记必须与原文逐字节一致，否则写回原始字节。
- **不覆盖你的文件。**索引页的位置上如果已有不是它生成的文件（比如你自己写的 `_moc/Home.md`），
  或者只差大小写的文件，这个索引页就跳过，并在报告里列出。
- **不碰特殊文件。**模板（「模板」「Templater」设置里的目录和日记模板）、Excalidraw 画板、Kanban 看板、
  索引页目录本身，一律不写。自动运行时跳过正在编辑的笔记，之后再补。
- **单篇退出。**在笔记的 frontmatter 里写 `vault-linker: ignore`，整篇不碰。
- **保留格式。**Windows 换行（CRLF）写回时保持不变。以一条 `---` 分隔线开头的笔记，区块前改用 `***`，
  绝不会把你的正文变成 frontmatter。

## 主题

「主题」就是用来判断两篇笔记是否相关的依据。插件不预置任何领域词，由这几个来源组合：

| 来源 | 是什么 | 默认 |
|---|---|---|
| 笔记标题和别名 | 每篇笔记的标题和 `aliases` | 始终 |
| 标签 | 你已经在用的 tag | 始终 |
| 主题词 | 你自己的词，每行一个，可带别名 | 空 |
| 从笔记里找 | 从 vault 里挖出的术语，勾选的加进主题词 | 按需打开 |

「从笔记里找」会把长标识符拆成单词；中文按 2–4 字片段，看它内部结合得多紧、左右邻字有多杂，不靠词典也能找出
真正的术语。在一个 762 篇的中文 vault 上，人工整理的 41 个领域词里有 39 个出现在候选中。向导给的是
可搜索的完整候选列表而不是前 N 名，因为少见的术语排名靠后，却同样重要。

## 性能

以标题和标签作主题实测（每轮都整库重算）：

| 篇数 | 每轮耗时 |
|---|---|
| 790 | 约 1 秒 |
| 3160 | 约 6 秒 |
| 6320 | 约 25 秒 |

主题匹配对每篇笔记只扫一遍（Aho-Corasick 多模式匹配），排序只比较共享主题的笔记。大 vault 开自动运行时，
可以在设置里把静默期调长，减少运行次数。

## 命令

| 命令 | 作用 |
|---|---|
| 预览（不改任何文件） | 只出报告 |
| 立即更新链接 | 写入、核对，失败则还原 |
| 显示上次运行报告 | 弹窗展示上次报告，可复制 |
| 从笔记里找主题词 | 从 vault 里挖候选术语 |

同一个引擎也能在 Obsidian 之外用命令行运行：

```bash
node tools/cli/cli.ts --vault <vault> --config <vault>/.obsidian/plugins/vault-linker-auto/data.json          # 预览
node tools/cli/cli.ts --vault <vault> --config <vault>/.obsidian/plugins/vault-linker-auto/data.json --apply  # 写入
```

## 配置可以分享

**设置 → 导入 / 导出设置**会把全部配置（包括领域和词表）变成一段 JSON，别人可以直接导入。

## 限制

- 只在 Obsidian 打开时运行（或用命令行）。
- 链接只写在文末区块里，不会把正文改写成行内链接，也不做语义向量。
- 不以换行结尾的笔记，第一次写入时会补一个结尾换行。
- 如果在文案设置里改了「本页由 Vault Linker 自动生成」这一行，用旧文案生成的索引页会被当作别人的文件跳过；
  删掉它们即可重新生成。

## 开发

```bash
npm install
npm run typecheck
npm test            # Node（22.18+）直接运行
npm run build       # 生成 main.js
```

- `src/core/` 是引擎：纯函数，不依赖 Obsidian，测试和命令行都直接用它。
- `src/obsidian/` 是很薄的一层 Obsidian 适配（读、写、设置、监听）。`runner.ts` 和 `watch.ts` 只依赖 API
  的一小部分（鸭子类型），所以 `tests/adapter.test.ts` 能用内存里的假 vault 跑通
  读取 → 计划 → 写入 → 核对 → 还原 的全过程。
- 被 `node --test` 直接导入的模块只用可擦除的 TypeScript 语法（不用 `enum`、`namespace`、参数属性）。

### 发版

```bash
npm version patch   # 同步改 package.json、manifest.json、versions.json，并打 tag
git push && git push --tags
```

推送 tag 会触发 `.github/workflows/release.yml`：测试、构建，并建一个带 `main.js`、`manifest.json`、`styles.css`
的草稿 Release，检查后手动发布。tag 必须与版本号完全一致、不带 `v` 前缀（`.npmrc` 里设了 `tag-version-prefix=""`）。
